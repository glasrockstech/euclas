# Development method

Build Euclas through small verifiable end-to-end increments, measured by accepted useful functionality, safety and total user effort rather than generated code volume. Discuss with the founder in Traditional Chinese; technical specifications/code documentation are English. Agents are replaceable because decisions, contracts, tasks and actual evidence persist here.

## Preparation and authority

Read the local project entry, current progress/authorization, domain vocabulary and chosen task owners. Existing product choices in design/decisions.md are settled unless new requirements/failure evidence reopen them. Qualify exact implementation/provider/native choices; do not invent support or fees. Use only the primary workflow for the phase plus complementary skills for distinct needs.

Current documents are a complete starting baseline, not executable product. Do not reimport old code/history or recreate the entire product interview. Fresh task state and runtime evidence start empty. Installation/runtime/external integration need their actual scope; templates and agents cannot grant it.

## Delivery loop

1. Select the smallest dependency-ready authorized behavior from plan.md. Read its GR/T requirements, exact contracts and security baseline only; do not load the entire catalog by default.
2. Publish/resolve any interface gap before dependent code. Define observable permitted/denied/stale/duplicate/recovery acceptance and exact enforcing owner. Proposal status is not user confirmation.
3. Implement fresh with one writer per shared area. Reuse concepts/invariants in this design, not old source/tests. Keep narrow explicit module ports, no speculative services/dependencies.
4. Validate untrusted input and execute meaningful focused tests. Use real DB/OS/provider/document evidence where required; static shape/fixture checks cannot replace it. Do not weaken failed assertions, skip tests or lower thresholds.
5. Obtain independent review of exact scope and source/diff, including relevant connected logic; fix findings and reverify changes. Security/recovery/public interfaces and milestone closure require fresh-context review.
6. If Git integration is authorized, preserve exact base/head/checks and integrate one small slice per branch/PR. Local review is not remote branch protection, signing or deployment authority.
7. Update progress with actual commands/outcomes, unsupported cases and remaining requirements. Advance only when dependencies have their required evidence. Continue independent authorized work when one operation is blocked.

## Parallel coordination and human load

Parallelize settled independent modules; use separate worktrees for concurrent code writers and one integration owner. Define task contract: accountable Actor/Assignment, scope/inputs/criteria, outputs/evidence, permissions, limits/deadline, model/route qualification, dependencies, review/escalation and completion/recovery. A subordinate asks its authorized supervisor before creating a human attention request.

Batch human-only prerequisites per milestone (test devices, consented source, provider login, install/resource scope, license/signing). Never ask for credentials in chat or repeat existing authorization. Resolve reversible technical details autonomously; ask one clear concrete question for unresolved consequential scope/security/cost/authority.

## Toolchain and environment

Direction: TypeScript strict on pinned compatible Node LTS/pnpm, workspaces behind just; PostgreSQL business data; Electron and React Native/Expo. Exact pins/framework/native tooling must be selected from current official sources and qualified for the first task. A future installation proposal states exact versions, license, scripts/downloads/resources, commands, cleanup and cost. No tool or dependency has been installed here.

Implement small reproducible setup/dev/check/test/build commands as needed; document their actual behavior. Do not list commands as runnable before they exist. Future CI uses declared OS/module matrices, deterministic contract generation and focused test gates; included quota/no added spend unless authorized. CI/build results are not native packaging or real-user acceptance.
