# Acceptance strategy and required behaviors

The [catalog](acceptance/scenarios.json) contains118 current behavioral specifications:101 initial-release cases and17 separately qualified roadmap cases. All have runtime_status `not_run`. IDs support requirement traceability, not a transferred completion history. Each requirement in [the registry](requirements.json) is covered, and the complete initial scope remains intact.

## First Desktop journey

On a declared actual Mac tuple: clean installer, real official Account login/local binding, persistent assistant with committed bounded source/criteria, real qualified Run/harness, durable editable DOCX and readable rendition, trusted verification, actual-human acceptance, reopen exact accepted bytes/version. Include negative access/revoke/revision/result/source cases. A mock login/provider, imported draft, format check, DB-only record or window opening cannot close this journey.

An early milestone is narrower than the release: Windows, invited people, native phones, plugins,2D organizations, full knowledge/chat, both harness targets/local-cloud and long-task upgrade still need their release evidence.

## Minimum cross-packet failure matrix

| Packet | Required permitted and adversarial behaviors |
|---|---|
| CP1 identity/admission | Actual Account proof/device/purpose/Instance binding; wrong host/key/person, replay/parallel redeem, rate/expiry, local-commit response loss; fixed24h ceiling, sleep/reboot/rollback/revoke/reconnect; account recovery consumes once and never grants local rights |
| CP2 work/outcomes | Proposal/commit/start exact rights; immutable Result/Evidence/Acceptance; live Run, stale criteria/result/manifest/producer, forged human/verifier, missing bytes/fail/not_run reject; duplicates do not create another acceptance |
| CP3 execution | Atomic start/budget/outbox before dispatch; lease/epoch and old-worker fencing; callbacks/retries/cancel/handover; lost provider reply stays unknown with original key and held reservations; no hidden auxiliary API route |
| CP4 bytes | Actual MIME/hash/size/source/transform/rendition bounds; hostile archive/script/path/mount rejection; trusted durable proof before available metadata; blob-before-metadata and commit-before-reply crash reconcile without overwrite/loss |
| CP5 runtime | Native authenticated peer/controller, exclusive ownership, precise readiness and manual stop; wrong/stale/replayed maintenance permit; new UI ready before old exit; preparation expiry/failed replacement retains old work; incompatible writers defer; no forced long-Run kill |

Every mutating command requires allowed/denied/stale/identical-duplicate/conflicting-key tests. Each authority-sensitive lock wait rechecks rights after the wait. Recovery requires actual crash-window tests; a normalized vector is not concurrency evidence.

## Independent release gates

- G1: bounded PostgreSQL and Temporal candidates compared on the same Desktop, transaction, lease, retry/cancel, checkpoint, restore and version traces. Business DB choice is not engine selection.
- G2: each real Executor/model/tool profile enforces current file/network/credentials/resource/descendant constraints and stop/revoke/recover. OpenShell first; alternative must satisfy the same conditions.
- G3: signed app-managed no-Docker installation and lifecycle/recovery/data preservation on every claimed OS/architecture. Linux/container/build-only evidence is insufficient for macOS/Windows or native mobile.
- G4: a real eligible subscription user obtains useful exact-version accepted outcome without API key/additional API bill, with all planning/summary/translation/knowledge auxiliary calls audited. Test absence of API keys plus an unrelated key as a trap, entitlement/quota/auth failure and no-overage. Local and cloud routes each qualify.

## People, scope and measurement

Observe actual non-programmer users/owners in en/zh-Hant with declared supported installations; review German catalogs/reports, and separately plan German participant observation. Record setup help and in-product rescue, source fidelity, accepted/rejected results, user briefing/review/correction time, cost/unknown usage and repeat use, including failures/dropouts. A proposed8-of10 first-result threshold and80% adoption/30% time-saving research targets are not confirmed promises or measured performance.

Use declared reference load (3 roots,5 Unit levels,100 concurrent non-executing queries and10 bounded simulated Runs) as an initial test input, not user-scale capacity. Measure persistent identities, queued work, active Runs, provider concurrency, machine resources and human attention separately before making a thousand-assistant claim.

Roadmap cases include optional hosted migration, richer exports/import/OCR/PPTX, advanced staffing and engineering deployment profiles. Keeping their specifications does not install Docker or promote their release scope. Preserve platform-independent isolation/recovery obligations while implementing the native initial product.

## F00 correction acceptance and deferred tool qualification

Static review must prove offline resource-ID/reference closure using active schema base URIs, every runtime lifecycle state is represented in IPC status, one three-attempt retry policy with delays1/5, and Desktop coalesce-only configuration. Require an explicit Result-freeze → evidence-record → submit → verify → acceptance trace, including partial/failed evidence, actual human judgment, stale/denied/conflicting requests and separate receipts. Source/team bootstrap packets and Mac distribution evidence are blocking prerequisites of their earliest consumers under plan.md.

F01a must run the selected real standards-compliant resolver/validator/generator on all public roots, positive/negative witnesses and freshness/equivalence checks. No installer or runtime tool was run to satisfy this static F00 correction. All product scenarios remain not_run.
