# Experience and first validation journey

## First Desktop slice

The first integrated validation target is: actual Desktop sign-in → a persistent assistant receives a bounded task → real qualified execution → durable editable document/readable rendition → formal submit/verify/actual-human accept → reopen and read the same accepted version.

Use a non-developer owner preparing a client proposal from supplied materials; a mailbox connection is optional. This first slice does not remove the complete-release mobile/human/plugin obligations.

1. Install and open. App-managed runtime truthfully shows Starting, Needs sign-in, Ready or Needs attention. No Terminal, Docker or provider infrastructure configuration by the ordinary user.
2. Sign in through official Email-code Account authentication and bind the verified person to this local Instance through protected native setup. Account identity does not grant organization membership by itself.
3. Meet one assistant and describe the proposal. Clarify missing audience, scope, deadline, source or commercial constraints only when consequential. Do not require an org tree or model selection to begin.
4. Show a bounded proposal: outcome, criteria, source access, responsibility, cost/time limits and next report. Already authorized details need no repeated approval. New access/sending/purchase authority is a separate concrete decision.
5. Commit and start through separate formal commands/receipts. The coordinator selects qualified routes, dependencies and bounded parallel work; delegated assistants use their own mandate. User sees meaningful progress and can stop.
6. Produce a versioned DOCX plus qualified PDF/readable rendition, with sources, exact versions, assumptions and limitations. Failed parsing/conversion is explicit; fabricated or unavailable checks remain not_run.
7. Supervisors resolve ordinary quality issues. Owner sees the business judgments requiring them—price, promises, uncertain facts, exception requests—next to the result, with in-place replies. The owner's explicit decision can sequence evidence recording, submission, verification and acceptance, with distinct receipts, returned revisions and exact target checks.
8. Reopen and read the exact accepted version, its evidence and remaining next actions. Acceptance does not imply an external Email was sent or a PR merged.

## Continuing work

Users can name/pin and message any authorized assistant or human. Work home emphasizes decisions, blockers, due work and reviewable results, then accepted outcomes; ordinary retries remain in details. A user's preferred/resume view does not bypass permissions.

On app return, show a permission-filtered briefing. Missed recurring reviews coalesce once under current authorization/budget; no storm of replayed schedules. On manual quit the local runtime fences/stops; the phone truthfully shows an unavailable host, without another dispatcher or Cloud continuation.

## Reading, discussion and plugins

Desktop and mobile show the same exact content/version/units/warnings and current permissions. Use reflowable content, complete accessible tables, data-backed charts, citations and visible fallback for unsupported parts. Focus/back restores reading position and draft when still authorized. A newer result never silently replaces the version being read or accepted.

General chat is separate from contextual work discussion. Each reply/selection targets an immutable version and current audience. Authorized supervisors may inspect work under an explicit oversight/read mandate; rank grants no access to private DMs or restricted sources. Later participants see only history permitted by current rights.

Private plugins belong to their personal/Unit scope. AI helps define, test and preview a dashboard before activation. Company templates can be customized by departments; upstream changes are reviewed for rights/data compatibility and retain a working version on conflict. Untrusted HTML has no Node, raw DB or provider secrets and acts only through validated host capabilities.

## Ten complete experience contracts

Install and understand host capabilities; begin with an assistant; control each assistant workspace; choose qualified local/cloud intelligence; retain company knowledge; add useful tools without becoming an integrator; delegate a continuing outcome; stop/revoke and regain control; understand results/cost/attention; preserve the organization when changing machines/models. Their exact GR-EXP requirements and failure criteria remain in the normative catalog.
